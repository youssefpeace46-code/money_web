# سوق المشير المالي

نسخة أولى عملية، عربية بالكامل ومتجاوبة، لسوق إعلانات بيع وشراء العملات والخدمات المالية. المنصة **لا تستقبل الأموال ولا تنفذ الصرف**؛ وظيفتها نشر العرض بعد مراجعته وفتح محادثة WhatsApp بين الطرفين.

## ما تم إنجازه

- صفحة رئيسية RTL، بحث وتصنيف وبطاقات عروض متجاوبة.
- نموذج زائر بلا حساب؛ كل عرض يدخل بحالة `pending` ولا يظهر قبل موافقة المدير.
- لوحة إدارة في `/admin.html` لإضافة العروض والأخبار، الموافقة والرفض والإخفاء والحذف.
- قاعدة Supabase مع RLS؛ صلاحية الإدارة محفوظة في قاعدة البيانات وليست مجرد إخفاء أزرار.
- منع تكرار العرض نفسه لمدة ساعة، تحقق على قاعدة البيانات، حقل مصيدة للبوتات، وحدود أطوال.
- PWA مع manifest وService Worker وأيقونات SVG نصية عالية الجودة وزر تثبيت وتعليمات iPhone. طلبات Supabase لا تُخزّن في Service Worker، لذلك لا تظهر أسعار قديمة بوصفها حديثة.
- وضع معاينة واضح عند عدم ربط قاعدة البيانات؛ كل سعر فيه موسوم بأنه تجريبي.

## التشغيل محليًا (اختياري)

```bash
npm install
cp .env.example .env
npm run dev
```

يمكن تنفيذ كل خطوات النشر التالية من المتصفح، ولا تحتاج إلى VS Code أو Android Studio.

## إعداد Supabase

1. أنشئ مشروعًا مجانيًا في [Supabase](https://supabase.com/).
2. افتح **SQL Editor**، والصق محتوى `supabase/schema.sql` ثم اضغط Run.
3. من **Authentication → Users** أنشئ مستخدم المدير ببريدك وكلمة مرور قوية.
4. في SQL Editor نفّذ الأمر التالي بعد استبدال البريد:
   ```sql
   insert into public.admin_users(user_id)
   select id from auth.users where email='YOUR_EMAIL';
   ```
5. من **Project Settings → API** انسخ Project URL و`anon`/publishable key. المفتاح العام مصمم للاستخدام في المتصفح؛ **لا تستخدم service_role إطلاقًا** في GitHub أو الواجهة.

## النشر من المتصفح عبر Cloudflare Pages

1. ارفع المشروع إلى مستودع GitHub.
2. أنشئ حساب Cloudflare (الخطة المجانية تكفي للبداية)، ثم **Workers & Pages → Create → Pages → Connect to Git**.
3. اختر المستودع واضبط: Build command = `npm run build`، وBuild output = `dist`.
4. من **Settings → Environment variables** أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` للقيمتين السابقتين، ثم Deploy.
5. سيعطيك Cloudflare رابطًا مثل `https://souq-al-mashir.pages.dev`. يمكن لاحقًا شراء نطاق مخصص وربطه من Custom domains.

GitHub وSupabase وCloudflare Pages توفر خططًا مجانية مناسبة للبداية. قد تدفع فقط عند تجاوز حدود الاستخدام، أو شراء نطاق خاص، أو إضافة خدمة CAPTCHA/رسائل مدفوعة مستقبلًا.

## النشر الصحيح على GitHub Pages

لا تختر النشر المباشر من جذر الفرع، لأن GitHub سيعرض ملفات المصدر قبل أن يعالجها Vite، فتظهر الصفحة بلا تنسيق. أضيف مسار GitHub Actions يبني الموقع وينشر مجلد `dist` تلقائيًا:

1. افتح **Settings → Pages** في المستودع.
2. من **Build and deployment → Source** اختر **GitHub Actions**.
3. افتح تبويب **Actions** وشغّل **Deploy to GitHub Pages**، أو ادفع تحديثًا إلى فرع `main` أو `work`.
4. بعد نجاح المهمة افتح الرابط الذي يظهر في خطوة **Deploy to GitHub Pages**.

إعداد `base: './'` يجعل ملفات CSS وJavaScript والأيقونات تعمل سواء كان الرابط في جذر النطاق أو داخل مسار مثل `/money_web/`.

## الاستخدام اليومي من الهاتف

افتح `https://رابط-موقعك/admin.html` وسجّل الدخول. لن يستطيع حساب عادي الدخول للبيانات الإدارية ما لم تضف معرّفه إلى `admin_users`.

- **أول خبر:** اكتب النص والترتيب في «نشر خبر» واضغط نشر؛ يظهر مباشرة في الشريط.
- **أول عرض حقيقي:** أضفه من نموذج الإدارة لينشر فورًا، أو أرسله من الصفحة العامة ثم افتح جدول العروض واضغط «موافقة».
- كل تعديل يُحفظ على الإنترنت ويصل للزوار دون تعديل الكود أو إعادة النشر.

## ملاحظات الأمان والإنتاج

- لا ترفع ملف `.env`؛ هو مستبعد من Git. ضع القيم في إعدادات الاستضافة فقط.
- فعّل MFA لحسابك في Supabase إن أتيح، وعطّل التسجيل العام (Signups) بعد إنشاء المدير.
- حماية التكرار الحالية مناسبة لنسخة أولى. عند زيادة الزيارات أضف Cloudflare Turnstile إلى النموذج والتحقق الخادمي عبر Supabase Edge Function لمنع السبام المتقدم.
- لا تُدخل أسعارًا حقيقية إلا بعد التحقق منها، واحذف بيانات المعاينة بمجرد ربط Supabase (لن تظهر تلقائيًا بعد الربط).
